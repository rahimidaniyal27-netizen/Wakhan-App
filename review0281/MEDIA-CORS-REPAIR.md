# Streamed native-app response headers

Operator's phone-path check after the matched-family repair verifies public AAC signal for both the current salon song and the reference song, with valid206/Content-Range replies for public Android-like, iOS initial two-byte andHEAD requests. Preparation8.74/9.24s is below the bundled client's20s deadline for these samples. First cold salon sample timed out at8s; a subsequent public request succeeded2s later. The native-phone failure itself remains unobserved. The user corrected the Android selection; investigation currently concerns iPhone. No rawphone request records were found by the nginx summarizer, which is not proof that the phone made no requests.

One verified wire-level defect: allowed-origin media responses lack Access-Control-Allow-Origin. The current `native_cors` middleware modifies headers after awaiting the handler; streamed handlers already callStreamResponse.prepare and send their headers before returning. RealHTTP tests reproduce the old206 without CORS while bufferedJSON receives headers.

The patch registers an on_response_prepare callback to apply the existing exact origin allowlist before headers are sent. `https://localhost` and `capacitor://localhost` remain the only allowed origins. No wildcard or credential allowance is added. ExistingVary tokens are preserved andOrigin deduplicated. TrustedHEAD preflight is supported along with existingGET/POST. Media leases and account authentication remain enforced; allNativeApp methods except route registration are unchanged byAST comparison.

`repair-media-cors.py --apply` requires the installed nine-file matched playback cohort, the known native-header source and the pinned local repair/backup installer. It compiles the candidate as the actual service user, backs up only wakhan_app_native_n1.py, and restarts onlywakhan-app. It verifies unchanged sign-in config/health/unauthenticated API rejection, public media bytes+CORS for both allowed origins, absence of CORS permission for an untrusted origin, publicFFmpeg signal, and current salon headers when the owner is still a member. Any verification failure restores the header file, retaining user messages and the previous playback/browser repairs. An offline source-only rollback command is printed.

Eleven tests pass onPython3.12: oldbug reproduction, realwire headers/bothorigins, range/HEAD/preflight, untrusted origins, lease/account authorization, unchangedauthAST, actualroute callbackregistration, one-file installation, failure preservingnewmessages, offlinerollback, and publicheader verification gates. Four installer tests also pass onPython3.13. No native build or phone playback success is claimed. This is a confirmed response-header correction, not proof that CORS caused every reported nativeAVPlayer failure.
